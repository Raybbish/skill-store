# OpenCode 懶人包 — AI Agent 安裝入口

使用者把這個 repo 網址丟給你、說要安裝時，照以下流程執行。

> 🎯 **這份檔案的工作是「問清楚再動手」，不是「一口氣裝完」。**
> 對象是零程式基礎的老師，裝錯比裝慢貴得多。

---

## 步驟二：問使用者要裝哪些

```
以上是這份懶人包的所有項目。

你可以：
- 輸入「全部」→ 依編號順序一包一包裝（#05、#06 會自動跳過，還沒寫好）
- 輸入編號組合 → 例如「00, 01, 03」只裝這三個
- 第一次用、不知道選什麼 → 建議先做「00, 01」，那是地基
- 已經裝過的項目 → 告訴我，我會跳過

你要安裝哪些？
```

**等使用者回答，不要自己決定。** 沒回答就不要開始裝。

### 順序與前置檢查

- 使用者選了 #03 但沒做過 #00／#01 → **先提醒**：「這包需要先完成 #00 和 #01，要順便一起做嗎？」等他回答。
- 不管使用者用什麼順序報編號，**實際安裝一律照編號由小到大**。
- 使用者選到 #10 但沒做過 #09 → 提醒他 #10 的範例需要一把 API 金鑰，問要不要先做 #09。
- 🔴 執行 #10 時：**沒有使用者明確同意，不准跑 `netlify deploy --prod`**（一次扣 15 點，每月只有 300 點）。預設一律草稿部署。

## 步驟三：一次裝一包

對使用者選的每一個 skill：

```bash
npx skills add mathruffian-dot/opencode-lazy-packs --skill <skill名稱> -g -y
```

> ⚠️ 如果 `npx skills add` 不能用（環境不支援、沒有網路、公司電腦擋住），改為**手動安裝**：
> 讀取 `skills/<名稱>/SKILL.md` 的完整內容，照裡面的步驟一步一步執行。
> 內容是一樣的——一鍵安裝只是把同一份檔案放進 `~/.config/opencode/skills/`。

`extras/` 的兩包不在 `skills/` 目錄下，一鍵安裝不一定抓得到，直接讀 `extras/<名稱>/SKILL.md` 照做。

### 執行時遵守

1. **先偵測再安裝**：已經有的工具不要重裝。
2. **每步都要驗證**：跑驗證指令、看到預期輸出才算過。
3. **需要人動手的地方停下來**：登入、授權、輸入驗證碼、需要管理員權限——講清楚要做什麼，等使用者回覆。
4. **不要代填金鑰或密碼，不要幫使用者選付費方案。**
5. **Windows 一律用 PowerShell，串指令用 `;` 不要用 `&&`**（PowerShell 5.1 會語法錯誤）。
6. **失敗就停下來問**，不要自己改指令硬闖、也不要跳過去裝下一包。

## 步驟四：每包裝完都要回報

依該 skill 檔案裡的「完成回報格式」回報。然後：

- 還有下一包要裝 → 說一句「接下來是 #XX」，繼續。
- 全部裝完 → 列一張總表：

```md
## 安裝完成

| 懶人包 | 結果 | 備註 |
|--------|------|------|
| #00 環境建置 | ✅ / ⚠️ / ❌ | |
| #01 連接模型 | ✅ / ⚠️ / ❌ | |

- 需要你手動處理的事：（沒有 / 條列）
- 建議下一步：
```

（✅ 完成 ／ ⚠️ 部分完成 ／ ❌ 失敗，失敗一定要寫原因。）

## 補充說明

- **完整內容都在 `skills/<名稱>/SKILL.md`**，需要細節時直接讀那份檔案，不要靠這張表推測步驟。
- 版本紀錄只看 `CHANGELOG.md`，各技能檔內不再標版本。
- 更詳細的 repo 導覽（編號原則、使用者說什麼該去哪一包、修改本 repo 的規則）在 `AGENTS.md`。
- **不要一次把整份研習裝完**，除非使用者明確說「全部」。裝一包、回報、等指示，是這份入口的預設節奏。
