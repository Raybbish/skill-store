# ADR 0021 — 公海讨论区:自由讨论升一等内容类型,自建不租
- 日期:2026-07-09
- 状态:已采纳(用户裁决:「讨论区先当作真实需求」)

## 背景
ADR 0017 把社区收敛为对象锚定四内容类型,但**无对象可挂的话没有家**:「有没有做 X 的 skill?」「你们打算支持 Y 吗?」、一般性反馈与闲聊,既不属于某个 skill 的短评/Q&A,也不是官方 blog。曾考虑「先租后建」(giscus/GitHub Discussions 试需求,周新帖 >20 再自建),被裁决推翻,理由:①giscus 要 GitHub 登录,与「用户面含大量不会 GitHub 的人」的既有定位直接冲突;②账号基建(email OTP,砖二)已落码,自建增量成本只剩一张表和一页;③需求判定不再需要代理指标——直接当真实需求建。

## 决策
**/talk 公海,形态最薄**(2026-07-09 与 P0 上线同批):

- **数据**:`posts` 表(迁移 `2026-07-09-talk.sql`)——楼 + 一层回复(触发器拒绝更深嵌套),纯文本 ≤2000 字,自选署名(默认「用户」)。
- **门**:匿名可读;发言只需登录(email OTP,延迟注册)——**不设回执门**,公海是说话的地方,不是评价凭证(短评的双层门不适用)。
- **闸**:每用户 60 秒一条(触发器);反刷哲学同 ADR 0017:闸不是门。
- **治理**:本人可删(删楼级联删回复);审核后台暂无,SQL 兜底;`official` 主理人标只能服务端置位(RLS 插入强制 false),防冒名。
- **冷启动**:商店供血——上线首日由主理人发署名帖(开店说明/本周收录/复盘),build in public 内容天然属于公海。红线不变:机器不代写,人写署名。
- **不做**(M2 按需):通知、富文本、分区、编辑、点赞、审核后台。ADR 0017 的 /community 聚合页密度门槛(周新帖 >20)不变——公海是发言区,聚合页是对象内容的聚合,两回事。

## 后果 / 约束
- 待用户端:Supabase 执行 `2026-07-09-talk.sql`;生产 Auth 回跳白名单需含 `/talk/`所在域名(与短评同一配置)。
- Supabase 内置邮件限额极低(每小时个位数封),公海放大登录量——**自定义 SMTP(如 Resend 免费档)升为上线前置**,顺带解锁输码轨(模板含 `{{ .Token }}`)。
- 界面文案照旧只写事实;空态一句「还没有帖子。」,不写鼓动语。
- 若公海长出对象锚定内容(某 skill 的讨论),暂不搬家;M2 做「挂到对象」的迁移工具再说。
