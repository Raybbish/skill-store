# ADR 0011 — 安全扫描整套功能下架(待重新研究与设计后再上架)
- 日期:2026-07-04
- 状态:已执行

## 背景
M0 期的安全扫描链路(L1 静态签名 → L2 脚本数据流五因子 → L3 LLM 意图审查 → 人工复核)与其产品面(CertBadge 认证徽章、权限营养标签、审计文案、CLI 装前披露)是快速搭出来的第一版。裁决口径、误报率、措辞边界、人工复核吞吐等都需要系统性研究后重新设计,现阶段继续对用户展示反而构成不可靠的信任暗示。

## 决策
**整套下架,后续详细研究与设计后再上架。**

- **前端**:`CertBadge` 组件删除;`SkillRow` / 详情页去徽章;首页「仅无网络请求」筛选移除;审计/认证/权限披露文案全站清除;`SkillCard` / `Skill` 类型剥离 `status` / `risk` / `evidence` / `review` / `l3` 字段;`build-index` 场景包不再要求成员 `pass`。
- **CLI**:装前权限营养标签与审计状态披露移除;**content_hash 逐文件哈希校验保留**(完整性校验≠安全扫描,是收录锚点)。
- **管线**:`audit` / `review` / `audit:l3` 从根 `package.json` scripts 移除;`scanners/` 与三个 job 源码**保留在仓**并加 ⛔ 停用头注,仅作重新设计参考。`eval`(质量评测)不属于安全扫描,保留。
- **数据**:catalog 里已有的 `skill-report.json`(含 `security_audit` 字段)原样保留,前端不再读取。

## 不下架的东西(容易误伤)
- content_hash 完整性校验(CLI / 安装器 / zip)。
- 发布者认证(`publisher_verified`,身份验证,非安全扫描)。
- 收录口径入口(browse 比例条 / nav「收录」tab / 页脚「收录标准」)。
- 评测(eval)链路与社区评测挑战。

## 重新上架的前置(留给未来的研究)
- 裁决口径与误报率的系统评估(L3 最终裁决 vs 只升不降,见旧口径记录)。
- 措辞红线重审(「已扫描/已评测」披露语义)。
- 人工复核吞吐与队列设计。
- 徽章的视觉与语义(认证 vs 披露)。
