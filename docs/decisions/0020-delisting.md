# ADR 0020 — 退市机制:上游消失/改名条目的墓碑与复活
- 日期:2026-07-09
- 状态:已采纳

## 背景
目录只会生不会死:mattpocock 把 to-prd/to-issues 改名 to-spec/to-tickets,旧条目带着镜像滞留货架、还是 product 包成员,CLI 从上游安装 404(2026-07-09 手工修复一次)。Code Search 采集器(ADR 0019 S1)日扫 30 新仓,长尾仓死亡率远高于官方仓,问题面只会扩大。另:sync 无删除语义,S0 手术的 692 条靠手写 SQL 清理(2026-07-09-s0-cleanup.sql)——目录的「死」需要一等公民机制,不能次次手术。

## 决策
**缺席计数 → 墓碑 → 自动复活**,三个动词全自动,零人工。

1. **缺席观测,两条线共用一个计数**(`pipeline/delist.ts#markMissing`):
   - **ingest**:本次成功枚举的仓(完整候选集在 `--limit` 截断前记录,漏访问的仓不判),存量条目不在候选集 → 缺席;官方仓 clone 报错含 not-found/could not read(删除/改私有)→ 全仓缺席;网络类错误不计。
   - **enrich-stars**:仓级 API 404 → 全仓缺席(每日 cron 按仓打 API,长尾仓——搜索采样源此后不回访的——的死亡由这条线兜)。限流/网络失败不计。
   - 计数按**观测日**幂等:`signals.missing_at` 同日多趟(ingest+enrich 同天)只计一次;已退市条目不再累计(零 diff 噪音)。
2. **墓碑**:连续缺席 ≥ `DELIST_STREAK`(默认 3 个观测日,env 可调)→ `meta.delisted_at` 盖章。**保留一切历史**:镜像、回执、认领、appearance、评价不动——退市是作品的状态,不是删除。
3. **复活**:任一采集路径重新观测到(内容变或不变)→ 清 `missing_streak`/`missing_at`、撤 `delisted_at`。上游改名回滚、误判(如临时改私有又公开)自愈,无人工介入。
4. **展示**:货架/索引/搜索隐藏(web visible 过滤);详情页保留 deep link 不 404,留一行事实:「上游已移除或改名,本条目于 X 停止收录;历史数据与镜像保留」;包成员缺失告警点名到 id(build-index,便于换新名或摘成员)。
5. **Supabase 传导**:`skills.delisted_at` 列(迁移 `2026-07-09-delist.sql`),sync 随行写入,复活传导为 null。**行永不删**——回执/短评/认领引用着它;读侧按列隐藏。S0 手术那种物理删除今后不再发生:先退市,物理清理(如果有)另行决策。

## 后果 / 约束
- 阈值 3 = 3 个观测日缓冲,防上游临时抽风;改名的仓 3 天后旧条目自动退市、新条目当天入库,无人工。
- 条目级判定当前只覆盖「本次被访问的仓」——官方仓每日全覆盖;长尾仓靠仓级 404(仓活着但单个 skill 被删的长尾条目,待该仓再次被任一源访问时才判)。接受此渐进性。
- 界面文案:只陈述事实,不用「拦截/下架/封禁」类执法语言(同 ADR 0019 口径)。
- 待用户端:Supabase 执行 `2026-07-09-delist.sql`;mattpocock 两条改名滞留条目将在 3 个观测日后自动退市(无需手工)。
