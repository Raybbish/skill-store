# ADR 0026 — 短评 → 评论区:多条 / 一层回复 / 顶踩,发言只需登录
- 日期:2026-07-14
- 状态:已采纳

## 背景
社区层原为「短评」(ADR 0017 砖二):一人一 skill 一条、必选好/一般/不好用一档、可选一句话,写入走双层门(登录 + 名下有该 skill 回执)。上线后主理人要更「活人感」的互动:同一个人能就一个 skill 多说几句、能回复别人、能对评论顶/踩。这三样都超出「一人一档验证短评」的形态,等于把评价区变成评论区。

此决策**部分反转**两条既有 ADR,明确记录以免口径漂移:
- **ADR 0017**「评价=已验证安装才可评」——验证从「门」降为「徽章」:发言不再要求回执,但「已验证安装」标记仍按作者回执由服务端盖章。
- **ADR 0024**「/talk 公海下线」——自由讨论以**挂在具体 skill 上**的形态回归(不是无对象公海),复用 /talk 已验证过的「一层回复 + 5 秒副闸」手法。原 /talk 的下线理由(冷启动无人、无对象可挂)不受影响:评论锚定在详情页的真实作品上,不是独立板块。

## 决策
就地改造 `reviews` 表与 `SkillReviews` 组件,**不新建独立社区页**。

1. **一人可多条**:去掉 `unique(user_id, skill_id)`。存量单条短评天然是「主楼评论」,零迁移。
2. **档位可选**:`verdict` 去 `NOT NULL`。主楼可以只写文字、只点档、或都要;回复行**不带** verdict/scene_tags(DB 约束 `reviews_reply_no_rating` 兜底)。
3. **一层回复**:自引用列 `reply_to`(删主楼级联删回复)。发帖闸 `tg_reviews_guard` 挡「回复回复 / 跨 skill 乱指」与「每用户 5 秒一条」——搬自 /talk,真防线仍在账号(登录),间隔是副闸。
4. **顶/踩,一人一票可反悔**:新表 `review_votes(review_id, user_id, value∈{-1,1})` 主键 `(review_id,user_id)`;切换走 upsert、取消走 delete。计数 denormalize 到 `reviews.up/down`,由 `tg_review_votes_count` 触发器维护——匿名列表直接读计数,不需聚合 RPC。前端乐观更新,失败回滚重取。
5. **发言只需登录**:插入 RLS 去掉 `review_allowed`(回执门),只留 `auth.uid() = user_id`;新增本人可删(物理删,评论区不留墓碑,同 /talk)。第一层门(登录)由 `to authenticated` 天然表达。
6. **「已验证安装」转生为徽章**:`tg_stamp_verified`(2026-07-14-verified-stamp-by-author.sql)不动,仍按**作者名下回执**盖章。门关掉 ≠ 虚标——没回执的评论就是没有标。诚实不变式延续 ADR 0017。
7. **「评于版本」语义微调**:主楼 `content_hash` 改记「发帖时货架内容哈希」(取自详情页 `contentHash` prop),内容更新后照旧显示「评于旧版本」。原语义「评价者回执版本」随回执门一并退场;回复不记版本。

迁移:`infra/migrations/2026-07-14-comments.sql`(幂等)。`app_settings.review_gate` 与 `review_gate_enabled/ review_allowed / review_eligibility` 谓词保留不删(无害),将来若要给「带 verdict 的评分」单独恢复回执门,现成。

## 后果 / 约束
- **聚合评分信号变弱**:同一人可多条带档评论,好/一般/不好用不再是「一人一票」的干净聚合。当前 UI 本就不展示聚合分,只列条目,故无立即破面;若日后要做「本 skill 口碑分」,需另立「一人一票的评分」与「多条评论」分离的模型(本 ADR 不做)。
- **验证拖拽流下线**:原「拖装好的文件夹/.skill 本地校验 → 落回执 → 过资格门」整套(webverify + ineligible 态)随回执门移除而不再触发。`lib/webverify.ts` 保留在仓内未删,将来若做「挣徽章」入口可复活。
- **反转成本**:ADR 0017/0024 的部分口径被覆盖;本文件为新口径唯一来源,阅读旧 ADR 时以此为准。
- **界面文案**:延续红线——只陈述事实,不用执法语言;顶/踩只给「顶/踩」二字,不加情绪化措辞。
- **待用户端**:①Supabase SQL editor 执行 `2026-07-14-comments.sql`;②前端随代码上线(env 未配时评论区自隐藏,与今天一致)。
