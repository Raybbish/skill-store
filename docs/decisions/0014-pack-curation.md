# ADR 0014 — 场景包:定义、收录标准与生命周期
- 日期:2026-07-05
- 状态:已采纳
- 关联:[0006 一键认领](0006-one-click-claim.md) · [0011 扫描下架](0011-unlist-security-scan.md) · [0012 verdict 服务](0012-verdict-service.md)

## 背景
场景包已上线(首发 8 套,`catalog/packs/*.json` → `idx/packs.json` → 首页跑马灯 + `/pack/[id]`)。原「成员全 pass 才出包」门槛随 ADR 0011 扫描下架而失效,需要把包的定义、现行门槛与长期收录机制固化,避免包在扩张中变质。

## 决策一:包是什么(三条逻辑,变了就不再是包)
1. **场景的答案,不是分类的子集。** 成员之间必须有互补性——工作流串联(生成→剪辑→渲染)或场景共现(写 Word 也要出 Excel)。判据:每对成员之间都说得出「为什么一起装」;整包能用一句话说清场景。同类堆叠是反模式(那是分类的职责)。
2. **包是信任放大器。** 包的信任 = min(成员信任);用户对包的审视比单个 skill 更少,出一次事烧掉的公信力按倍数计。成员出问题 → 整包隐藏,没有例外。
3. **稀缺即价值。** 包替用户做决定;包一多,选包又变成决定,自我瓦解。首页跑马灯 ≤ 12 个,总量宁缺毋滥。

## 决策二:收录门槛
**现行(扫描下架期,依 0011):**
- 成员 3–5 个,全部处于可见态(非 duplicate、frontmatter 合规、content_hash 在锚);
- 场景一句话 + 成员互补性说明(写在 pack PR 描述里留痕);
- 命名与文案零内部词汇(不出现 收录/来源/扫描/审计 等),说人话、说场景。

**verdict 服务上线后(0012)自动升级:** 成员 verdict 全绿才出包;任何成员 verdict 降级 → 整包自动隐藏(沿用 build-index 现有「成员缺失即跳过」机制,判据换成 verdict)。

## 决策三:收录机制三阶段(先编辑 → 再信号 → 再开放)
- **编辑期(现在)**:手工策展,不开放投稿。包需求**反向牵引排程**:想组某场景的包,优先跑该品类的评测/verdict——包是需求侧信号,不是库存清点。
- **信号期(M1)**:三个候选来源。① 共装信号:CLI 多目标安装组合的匿名聚合(埋点应尽早开始记);② 场景级评测:包在品类任务集上的整体表现进包页,是包最硬的公信力;③ 作者包:认领后的发布者(0006)可提自家搭配,平台守门槛。
- **开放期(M2)**:社区清单与官方包分轨——官方包 = 编辑策展 + 硬门槛 + 首页位;社区清单 = 自由创建 + 署名 + 不进跑马灯。复装率高的清单升格为官方包候选(与 labels promote 机制同构)。「合集」一词保留给社区清单,不得挪用。

## 生命周期与健康度
- 成员缺失/下架 → 整包隐藏(已实现);场景过时 → 归档不删(git 留痕);两包成员重叠 >50% → 合并;
- 核心健康度指标:**整套装完率**(装到一半放弃 = 包太肥或场景没想清);
- pack JSON schema 变更走本 ADR 修订,不另开。
