L1critical 签名 → L2五因子静态分析 → L3LLM 意图审查 → 人工复核放行 → 结论写回 skill-report.json → 前端渲染权限营养标签

三条设计红线

原则含义
只说「已扫描」全站措辞一律「已扫描」,绝不说「保证安全」。审计是信号披露,不是背书。
含网络必人工任何命中 network 因子的条目一律转人工放行,自动化不放行外联行为。
只升不降 · fail-closedL3 只能把风险往上调、不能下调;LLM 调用失败按「有风险」处理,不静默放过。已有人工签名的条目跳过重判。

代码模块

文件职责
scanners/rules.tsL1/L2 规则集 v1(critical 签名 + 五因子正则),单一来源
scanners/analyze.ts扫描引擎:逐文件套规则 → 填 risk_factors + evidence
scanners/llm.tsL3 LLM 客户端(OpenAI 兼容、防注入定界符、fail-closed)
jobs/audit.tsL1/L2 主入口 npm run audit,顺带哈希漂移检测

①L1critical 签名扫描

硬红线正则,scope: any 全文件扫。命中即判 needs_review——但不自动 reject,交人工定夺(避免误报直接毙掉合规 skill)。规则版本 rules-v1。

规则 id拦截目标
l1-aws-key内嵌 AWS Access Key(AKIA…)
l1-gh-token内嵌 GitHub token(ghp_/gho_…)
l1-private-key内嵌私钥块(-----BEGIN … PRIVATE KEY-----)
l1-pipe-shell远程脚本管道执行(curl … | bash)
l1-b64-execbase64 解码后执行 / eval(atob())(混淆)
l1-destructive破坏性删除(rm -rf / 或 ~)
l1-cred-paths引用凭证文件(.ssh/id_*、.aws/credentials、.netrc、.docker/config.json)

②L2五因子静态分析

按行为把风险归为四类因子 + 脚本清点,生成详情页那套「权限营养标签」。规则版本 static-v1。scope 控制匹配范围:script=脚本文件、fence=SKILL.md 代码块内(让 agent 执行的命令)、any=所有文本。

刻意排除的主要误报源:md 正文里的普通 http 链接是文档引用,不算 network。只有脚本里的真实网络调用、或 SKILL.md 指令让 agent 去拉远程 URL,才计入。
因子代表规则命中示例
networknet-py / net-js / net-socket / net-sdk / net-remote-inst / net-clirequests·fetch·socket;anthropic/openai SDK;指令 WebFetch 远程 URL;curl/wget/ssh
filesystemfs-write-py / fs-write-js / fs-escape / fs-home写删文件;../../ 越权;访问 ~/.ssh、~/.aws 等家目录敏感位
env_accessenv-py / env-js / env-shos.environ·process.env;引用 *_KEY / *_TOKEN / *_SECRET
external_commandscmd-py / cmd-js / cmd-osasubprocess·child_process;osascript·powershell
scripts(采集期清点)可执行文件数量 + 前 20 条 evidence,pre-audit 提示
L3 反哺的两条补丁:net-sdk——anthropic/openai 客户端的隐式网络(曾被 mcp-builder 逃过 L2);net-remote-inst——SKILL.md 里让 agent 拉远程 URL 并遵循的「远程指令面」(曾被 writing-guidelines 逃过)。两处均由真实 L3 跑出后回补进静态规则。

③L3LLM 意图审查

静态规则看「用了什么能力」,L3 看「意图是否恶意」。OpenAI 兼容接口,env 配 LLM_BASE_URL / LLM_API_KEY / LLM_MODEL,LLM_MOCK=1 空跑测管路。四条硬约束:

  • 防注入定界符:被审内容包在定界符内,skill 文本无法伪装成指令劫持审查器;
  • fail-closed:调用失败 / 超时按「有风险」处理,绝不静默放过;
  • 只升不降:L3 只能把 pass 提到 needs_review,不能反向下调 L1/L2 的结论;
  • 跳过人工签名:已有 review 签名的条目不再被 L3 覆盖。
真实跑记录(deepseek-v4-flash · 用户本机):19 条 → 14 clean / 5 升级,复核后全放行;两个真发现即上方 net-sdk / net-remote-inst 补丁来源。推荐分层:DeepSeek/Qwen 全量初筛 + 强模型复查可疑项,异构双模型交叉降低注入风险。

④人工复核放行

所有 needs_review 由人工经 jobs/review.ts CLI 处置(approve / reject),结论带签名 note 写入 security_audit.review 留痕。audit.ts 重审时检测到 prev.review 即保留人工结论,不被自动扫描覆盖。

⑤needs_review 判定逻辑

四个触发条件命中任一 → needs_review,否则 pass(逻辑在 audit.ts):

触发原因
L1 critical 命中疑似密钥 / 危险执行 → 人工定夺(不自动 reject)
network.present设计红线:含外联一律人工放行
env_access + external_commands读凭证类环境变量 且 执行外部命令 → 组合风险(外泄链路)
content_hash 漂移上游内容已变,采集期指纹失配 → 需重新采集重审
// audit.ts 判定(简化)
if (analysis.criticalHits.length) reasons.push("L1 命中 critical 签名");
if (factors.network?.present)      reasons.push("含外部网络请求(红线)");
if (factors.env_access?.present && factors.external_commands?.present)
                                    reasons.push("env + cmd 组合风险");
if (drifted)                       reasons.push("content_hash 漂移");
status = prev.review ? prev.status : reasons.length ? "needs_review" : "pass";

⑥运行与调度

npm run audit                 # L1/L2,默认只审 status=pending
npm run audit -- --all       # 全量重审
npm run audit -- --repo owner/repo  # 按仓过滤
npm run audit:l3              # L3 意图审查(需 LLM_* env)
node .../review.ts approve|reject <id>  # 人工复核留痕
