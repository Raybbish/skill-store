四条设计原则

原则含义
情报不当货skills.sh、awesome-list 等第三方站只提供「哪里有 skill、谁被精选、装了多少次」的发现与信号,内容一律回上游 GitHub 采集,不搬运任何第三方数据库。
收录有门槛GitHub 存在批量生成仓(实测单仓 26,134 个 SKILL.md)与聚合搬运仓。用「每仓折叠采样 + 合集条目」控制供给质量——与 SkillsMP(180 万条全收、噪音极大)的根本差异。
采集不冲下游评测(eval)/ 微文案(copy)/ 人工分类锁定(category_locked)在同 id 更新时按锚保留;判定(verdict)自 ADR 0012 起在 catalog/verdicts 独立账本、天然不受采集影响;内容未变时连文件都不重写(幂等,git diff 无噪音)。
归属还原同内容多处出现时 canonical 按「已有条目 > 官方源 > stars 最高」裁决,搬运仓标 duplicate_of 指回原作者。竞品均为先到先得或不去重,此为差异化点。

①供给源(五框全通)

按信噪比排序接入,全部汇入同一条采集管线。架构图中「awesome 精选仓」与「第三方 Hub 情报」在实现里合并为 hub-signals 一条线(精选清单既是内容线索也是信号)。

1. 官方精选仓 默认必跑

sources.yaml 白名单(当前 anthropics/skills、vercel-labs/agent-skills),量小质高、licence 清晰,是 catalog 的信任底座。owner 进入「官方源」名单,去重裁决中优先级最高。扩源加 yaml 条目即可,无需改代码。--source <repo> 可只跑单仓。

2. GitHub 全域 --github-search N(默认 100)

GitHub Search API 按 topic:claude-skills(GH_SEARCH_QUERY 可覆盖)搜仓库,stars 降序取头部,跳过 fork / archived,逐仓 clone。每条注入 stars_github。

防灌注 · 每仓折叠采样:单仓 SKILL.md 数超过 MAX_PER_REPO(默认 50)判定为批量源,只采样收录 N 条。采样优先级:frontmatter 合规 > 有 description > 原目录顺序(稳定排序,重跑一致)。被采样条目标 bulk_source: true;所有条目记 repo_skill_count 供排序降权——2.6 万个 skill 分摊同一份 stars,单条含金量远低于单 skill 仓。

合集条目:被折叠仓库额外产出一条 CollectionReport 写入 catalog/collections/<owner>/<repo>.json(总数 / 采样数 / stars / 上游 URL),前端可渲染「该仓含 N 个 skill → 去上游」合集卡片。参考 buildwithclaude 的 isMarketplace() 折叠,但保留 skill 粒度采样。

限制:search 上限 1000 条;需 api.github.com 可达 + GITHUB_TOKEN。topic 召回有限,后续可加 Code Search(filename:SKILL.md)扩召回。

3. awesome 精选信号 --hub-signals N(默认 300)

拉取社区精选清单 README(默认 VoltAgent/awesome-agent-skills,HUB_LISTS 可扩),解析条目与分类标题,按上游仓分组回 GitHub 采集。注入 curated_by(被哪些清单收录 + 分类)与 meta.category(补上采集拿不到的分类)。每仓上限 MAX_PER_REPO;带 subpath 的条目只收对应目录。awesome-list 是 MIT 公开 markdown,本就以被引用为目的;「被精选」比纯流行度更契合质量定位。

4. skills.sh 安装量榜 --skills-sh N(默认 200)

解析首页服务端渲染榜单(robots.txt 明确 Allow: /,仅 /api/ 禁抓),从链接 /<owner>/<repo>/<slug> 与锚文本尾部安装量(2.3M / 613.6K)还原条目,~280 条足够 top-200 信号。官方 /api/v1 文档声称免鉴权、实测 401 需申请 key,故不对接。

榜单条目按 slug 对上仓库内 skill 目录名或规范化 name,匹配不上静默跳过(由全域源覆盖);well-known 非 GitHub 源(如 open.feishu.cn)暂不支持。注入 installs_skills_sh——安装量 = 免费预筛。

验证记录(2026-07-02):top 50 → 16 仓 → 58 skill 入库,46 新增,重复 0。W2 衔接:/api/v1/skills/audit/{id} 返回 Snyk / Socket / Gen Trust Hub 伙伴审计结果(status / riskLevel),可作免费外部对照信号。

②采集管线(七环节)

所有源殊途同归:拿到 owner/repo 后进入 discoverFromRepo(),再由 ingest.ts 统一去重写入。

1 · shallow clone(git.ts)

git clone --depth 1 到临时目录(比 REST API 无速率限制、一次拿全仓),git ls-tree -r HEAD 取全量 blob 清单(path + blob sha),记录 HEAD commit 与分支。结束 cleanup 删除。

2 · SKILL.md 发现

文件树按正则 (^|\/)SKILL\.md$ 匹配,每个命中目录即一个候选(根目录也支持)。

3 · frontmatter 校验(frontmatter.ts)

agentskills.io 最小规范:frontmatter 存在、name 非空 ≤64 字符、description 非空 ≤1024 字符。写入 frontmatter_valid / frontmatter_issues。不合规不拒收(货架标记,下游处置),但折叠采样时排序靠后。

4 · 元数据提取

  • licence 双轨分流(license.ts):skill 目录内 LICENSE 优先,否则回落仓库根。文本朴素识别(MIT / Apache-2.0 / BSD / ISC / Unlicense / CC0);宽松 → hosting: mirrored(可镜像),识别不出 → local-file(needs-review) / none(all-rights-reserved) → indexed(仅索引跳转上游)。
  • 脚本清点 / 安全审计已从采集剥离(ADR 0011 + 0012):hash.ts 仍保留 inventoryScripts() 工具,但采集期不再写 security_audit——安全扫描整套下架待重设计(ADR 0011);判定迁至 catalog/verdicts 独立账本(锚 content_hash、服务侧 submit 触发,ADR 0012),不随采集产出。sync.ts 相应把 audit_status / risk_factors / … 列写 null。
  • 上下文体积(ADR 0015):写入 context_size,只表达静态装载边界,不承诺真实每次调用消耗。三类 scope:最小装载(SKILL.md)、含声明引用、文本包总量;旧 token_cost.body_tokens / chars/4 链路已下线。
  • 采集期归类(categorize.ts):按名称/描述/路径启发式打 meta.category(featured 主类,每 skill 归一个)+ meta.tags(非 featured 二级);category_locked 人工锁定则跳过重算;sources.yaml 可 per-source 覆盖类目。词表 schemas/src/labels.ts,featured 增删由 promote.ts 依数据自动提议(详见「分类与安装入口 · 实施拆解」)。

5 · 规范 ID 与 content_hash

ID(三段式 v2) = 小写owner/小写repo/normalizeName(fm.name || 目录名),与架构图 owner/repo/path 及 skills.sh 的 {source}/{slug} 对齐。content_hash = 目录内全部 (相对路径, git blob sha) 排序集合的 sha256——blob sha 本身内容寻址,无需读文件即得稳定指纹,CLI 安装时可同算法本地校验。溯源锚点:upstream(仓库内路径 URL)+ upstream_commit(HEAD),支撑每日 diff 与哈希漂移检测。

✅ 已迁移(2026-07-02):目录遍历统一走 catalog.ts;存量 73 条经 migrate-id-v2.ts 无损迁移(审计/复核保留);web 路由 [owner]/[repo]/[name] 与 CLI 同步更新。

6 · 去重与归属还原(ingest.ts)

跨运行 + 跨源,以 content_hash 为键:

  1. 已有 catalog 预填哈希表,已有条目优先当 canonical(稳定不漂移;优先取非 duplicate 条目,避免链式指向);
  2. 新哈希组内裁决:sources.yaml 官方源 owner > stars 最高者(官方源不注入 stars,必须显式优先,否则输给搬运它的高星聚合仓);
  3. 组内其余标 duplicate_of;同 id 覆盖更新不算重复;
  4. 同 id 去重:一次运行内保留第一条(源顺序:官方 → hub → 全域 → skills.sh)。

7 · 写入 catalog(幂等)

  • 路径 catalog/skills/<owner>/<repo>/<name>/skill-report.json,符合 skill-report.schema.json;
  • 未变跳过:content_hash 与 upstream_commit 都没变、且已归类 → 不重写,无噪音 diff;
  • context_size 外科式回填(ADR 0015):缺 context_size 的存量条目只补该字段进旧报告,其余(category / tags / copy / eval)原样保留、不走完整更新路径——避免启发式归类冲掉 categorize:llm 的权威判定;
  • 下游成果保留(采集只写元数据,不冲下游):eval 原样保留;category_locked 人工锁定的分类不被覆盖;微文案 copy 按 content_hash 锚保留(内容没变则沿用,含 M1 author 稿,ADR 0013),变了才交 categorize:llm 重算;判定(verdict)在 catalog/verdicts 独立账本、锚 content_hash,采集天然不会冲掉(ADR 0012);
  • 两段式镜像 + 单文件闸:默认索引层只写元数据;--mirror(INGEST_MIRROR=1)且 licence 为 mirrored 才拷贝完整副本到 mirror/(symlink 解引用落地)。镜像有单文件上限(MIRROR_MAX_FILE_MB,默认 2MB):超限文件跳过不入 git(挡编译产物 / 大 blob),该条目标 mirror_complete: false;
  • verdict 提交插拔点(ADR 0012,默认关):收录完成后 TRUST_SUBMIT=1 才异步 submit 变更条目触发判定(幂等);服务缺席 / 关闭时采集完整可用,收录永不等扫描;
  • 合集条目:catalog/collections/…,字段没变不重写;
  • 汇总统计:新增 / 更新 / 未变跳过 / 外科式回填 / 重复 / 保留 eval / frontmatter 不合规 / 待归类 / 镜像跳过大文件 / 批量源合集。

③调度与运行

本机

# 令牌
export GITHUB_TOKEN=$(gh auth token)

npm run ingest                                # 仅官方仓
npm run ingest -- --github-search 100         # + GitHub 全域
npm run ingest -- --hub-signals 300           # + awesome 精选
npm run ingest -- --skills-sh 200             # + skills.sh 榜单
npm run ingest -- --source anthropics/skills  # 只跑单仓
npm run ingest -- --mirror ...                # 托管层:下载镜像副本

GitHub Action(.github/workflows/ingest.yml)

  • 每日 03:00 UTC cron 全源:--github-search 100 --hub-signals 300 --skills-sh 200,timeout 120 分钟;
  • workflow_dispatch 手动触发可指定单仓;
  • 产出不直接进主干:开 PR(分支 ingest/<run_id>),人工抽查 licence 分流、frontmatter、duplicate_of、合集条目后合并;
  • Secrets:GITHUB_TOKEN(自带)。
