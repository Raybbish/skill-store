制品对象存储与 180 天保留

ADR 0029 的运维落地手册：把内容寻址的 .skill 从 Vercel 静态构建中解耦，发布到 S3 兼容对象存储，并以“首次发现无引用”而非上传时间计算 180 天保留期。

实现状态：代码完成，待配置灰度存储边界：S3 compatible默认保留：180 天删除默认：dry-run

1. 冻结结论

  • 对象 key 使用最终制品字节的 artifact_sha256，不是 source hash。
  • sha256/<hex>.skill 与 sha256/<hex>.json 只允许条件创建；同 key 不同字节必须失败。
  • index.json 是可更新指针；每次发布另存 releases/<git sha>.json 作为不可变发布快照。
  • 当前 index 与 ARTIFACT_PINNED_RELEASES 共同构成引用根；被引用对象不进入 GC。
  • 普通退市不会立即删除。只有明确 tombstone 且已从所有引用根移除的制品才可立即删除。

2. 发布链路

catalog mirror
确定性打包
本地双哈希校验
条件写入对象存储
Vercel 只携带 index

灰度开关关闭时，部署保持原行为，制品继续进入静态输出。设置仓库变量 ARTIFACT_STORE_ENABLED=1 后，构建把大对象写入 runner 临时目录，仅把 artifacts/index.json 放入站点；对象发布成功后才继续 Vercel 部署。

这允许先合并代码、完成 bucket/CDN 配置和 dry-run，再开启事实源切换，不会因未配置 secret 破坏现有生产部署。

4. 启用顺序

  1. 创建私有写入 bucket，并配置公开只读 CDN/域名。
  2. 写入上表 variables/secrets，但暂不设置 ARTIFACT_STORE_ENABLED。
  3. 本地或临时环境运行 npm run artifacts:publish -- --dry-run，验证构建目录、manifest、index 和 URL。
  4. 设置 ARTIFACT_STORE_ENABLED=1，手动触发 Deploy Web。
  5. 抽查任意 index URL：HTTP 200、字节 SHA-256 与 index 一致、缓存头为 immutable。
  6. 手动运行一次 Artifact Retention，保持 apply=false，确认 inventory 无异常。
rtk gh workflow run deploy.yml
rtk gh workflow run artifact-gc.yml -f apply=false
rtk gh run list --workflow "Artifact Retention" --limit 3

5. 180 天 GC 语义

每周任务列举 artifacts/sha256/，读取当前 index、pinned release 和 gc/state.json：

  1. 仍被任一引用根使用：永久保留，并从 orphan state 移除。
  2. 首次发现无引用：只写入 unreferenced_since，不删除。
  3. 连续无引用满 180 天：进入删除清单；--apply 才真正删除。
  4. tombstone：不等待 180 天，但如果仍被引用则任务失败，不制造线上断链。

每次 apply 会写入不可变审计记录 gc/runs/<timestamp>-<uuid>.json，包含对象数、总字节、近 30 天新增字节、孤儿数和删除清单。

发布快照采用独立规则：ARTIFACT_PINNED_RELEASES 永久保留；未 pinned 的 releases/*.json 保留 30 天后清理。快照过期不会改变制品自身的 180 天 orphan 时钟。

不要给整个 artifacts/ 前缀配置“上传满 180 天自动删除”的粗粒度生命周期规则；它会误删仍被当前 catalog 引用的老制品。

6. Tombstone 操作

仅在法律下架、许可证撤回或恶意内容处置时，把 hash 写入 infra/artifacts/tombstones.txt。先从 catalog 和所有 pinned release 移除引用，再合并并手动执行：

rtk npm run artifacts:inventory
rtk npm run artifacts:gc -- --apply

普通上游退市、仓库改名或临时不可访问不属于 tombstone。

7. 回滚

若对象存储或 CDN 灰度异常，将仓库变量 ARTIFACT_STORE_ENABLED 改回 0 并重新部署。构建会恢复相对 URL 与 Vercel 静态制品。对象存储中的不可变对象和 GC state 保留，不需要删除；修复后可再次开启。

8. 验收清单

  • 同一构建重复 publish：全部对象报告 existing，字节不重写。
  • 同 key 不同 manifest：条件写入失败。
  • current/pinned 引用对象：即使 state 很老也不删除。
  • 无引用对象：首次只登记，满 180 天后才进入删除清单。
  • tombstone 仍被引用：fail closed。
  • 生产灰度后：Vercel 输出不再包含全部 .skill，公开下载 URL 指向 CDN。
