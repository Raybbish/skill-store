Skill Store 竞品与市场调研

2026-07-02(2026-07-03 修订:评测重定位为可复现协议——平台做赛道不做裁判)· 面向「skill 届的 App Store」概念验证
一句话结论

发现(discovery)已是红海,信任(trust)与质量(quality)是空白。市场上没有一家同时做到「可复现评测 + 安全透明 + 效果展示」——这正是你 mockup 的定位,方向成立。

中国大厂入场2026-07 更新

ModelScope Skills 中心是重叠度最高的新玩家。阿里魔搭上线的 skill 聚合专区,定位「开源模型与 Skills 自由组合」,打法是全栈生态:网页目录(五大分类 + 关键词搜索)+ CLI 安装(npx skills add)+ 开源运行时 MS-Agent(含 ms-enclave Docker 沙箱)+ 免费 Qwen API 推理。镜像 @anthropics、@vercel-labs 等国际命名空间,同时接受社区上传。

对你的含义:它复制的是 skills.sh 的「大目录 + CLI 分发」模式——技能卡片只有名称/描述/作者/标签,没有评测分、权限披露或效果对比,你的五个差异化点在它身上依然零覆盖。真正的威胁在渠道:千万级社区流量 + 阿里云入口,一旦补上评测/安全层,中文市场的第三方店空间会被快速压缩。腾讯 SkillHub 的「50+ 精选 + 安全扫描」说明大厂已意识到信任问题,只是目前做得薄。

时间窗口:大厂当前都在抢供给规模和自家生态绑定(ModelScope 绑 Qwen/MS-Agent,腾讯绑 OpenClaw),中立评测层仍无人做。「多 agent 中立聚合 + 评测数据资产」的对策成立,但窗口期估计不超过 2-3 个季度。

质量危机是真实的。SkillsBench(87 任务、7,308 条轨迹)证明精选 skill 显著提升通过率,但公开 skill 平均质量低下,部分反而拖低表现。→ 质量差异真实,评测是刚需筛子——但要做成可复现协议(带元数据、可被复跑挑战),而非平台单方跑分。

安全危机更真实。SSH 密钥外传只需 SKILL.md 里三行 markdown;91% 的恶意 skill 同时用传统恶意代码 + 提示注入,能骗过现有扫描器;ClawHub 接入 VirusTotal 后仍被 Unit 42 抓到 5 个漏网恶意 skill。→ 纯自动扫描不可信,「扫描通过」必须配人工复核层级 + 权限透明标签,这是差异化护城河。

GPT Store 的前车之鉴。300 万 GPT 上线首日即噪音化,无变现框架导致创作者流失;后期按「粘性」付费也没救活。教训:先解决信任与质量,变现跟着高质量供给走,而不是反过来。

差异化机会按优先级 · 均为零竞品覆盖

1
可复现评测协议(赛道非裁判)2026-07 重定位
SkillsBench 证明质量差异真实但只是学术 benchmark;没有一家店把「任务集 + 确定性校验器 + runner」开放成可复现协议、让货架分数带元数据可复现可挑战。平台不做单方裁判,公信力锚在可复现性——与安全审计「已扫描≠保证安全」同构。
2
权限营养标签mockup 已覆盖
现有市场只有「通过/不通过」二值,没人展示「含 2 个 Python 脚本、仅工作目录读写、不联网」这种结构化披露。
3
效果对比替代截图mockup 已覆盖
同一 prompt 装/不装的输出对比,直击「skill 到底有什么用」的认知成本。
4
Token 成本标注mockup 已覆盖
GPT Store 教训里 token 成本吃掉收益是头号坑,「~3K token/次」是被验证的痛点。
5
冷启动用审计摘要占位评论
解决新市场无评价的鸡生蛋问题(评测成熟后并入可复现跑分摘要)。

风险

发行入口被平台截流。Anthropic / Vercel / 阿里 / 腾讯任何一家把评测 + 安全做进官方渠道,第三方店空间被压缩(参考 App Store 从未让位给第三方);中文市场尤甚——ModelScope 和腾讯 SkillHub 都自带流量与云入口。对策:先做多 agent 中立聚合(官方各自只管自家),评测数据本身沉淀为资产。
恶意 skill 漏网一次即重创信任。ClawHub 已示范。安全承诺措辞要留余地——「已扫描」而非「保证安全」。
