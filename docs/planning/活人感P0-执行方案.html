OH-MY-SKILL · 执行方案

活人感 P0 —— 零用户期的三个体温来源

重定位(ADR 0017 §背景)后性价比最高的一批活:编辑、作者、商店自己——三个不需要用户就成立的活人感来源。全部不依赖账号层、不动采集管线。

日期 2026-07-07 · 关联:社区层设计 v2(§0 设计公理)· ADR 0013(微文案)· ADR 0014(场景包)· ADR 0016(first_seen_at)

0 · 为什么是这三件

活人感的两个陷阱是零人社区与机器装人。零用户期唯一诚实的活人感来自三处:编辑(署名策展)、作者(供给侧本来就活着)、商店自己(build in public)。规模化的机器文案(5,800+ tagline)解决覆盖率,恰恰不提供活人感——几十段人写的、有署名的字,比一万条机器副标题更像有人在。

1 · 包页编辑手记(编辑的活人感)

最优先——纯内容 + 轻渲染,一天内可上线
形态每个场景包一段 80–200 字手记:为什么选这几个、怎么搭配着用、坑在哪。署名 + 日期,口语,允许有观点。
数据catalog/packs/*.json 加可选字段 editor_note: { text, author, date } → build-index 透传 idx/packs.json → /pack/[id] 渲染「编辑手记」块(引用体版式,署名右下)。
生产Claude 可出草稿,但定稿必须人过手改写并署名——机器写的标机器,人写的署名,这批属于后者。8 包 ≈ 一杯咖啡的工作量。
红线沿用 ADR 0014:零内部词汇(审计/采样/上游/收录不出现);不吹「保证」;手记内容只谈使用,不谈机制。

2 · 详情页作者行(作者的活人感)

供给侧本来就在真实地 commit,把它透出来
形态详情页头部一行(纯文字,守 v4 无图标版式):@publisher · 收录于 X 天前 · 上游提交 Y 天前。作者名已链 publisher 页,不新增路由。
数据·已有「收录于」= signals.first_seen_at(ADR 0016,10,010+ 条已有)。相对时间客户端算。
数据·新增「上游提交」需新字段 signals.upstream_commit_at:采集时 clone 已在手,git log -1 --format=%cI 零成本带出。新条目起攒,存量不回填,缺失整段隐藏——绝不拿 fetched_at 冒充。
不做作者头像(v4 纯文字版式 + 图标 IP 策略保守,ADR 0002);「最近核对」等内部语义不上货架。
诚实红线:fetched_at 是「我们最近一次采到」,不是「上游更新」——两者严禁混用文案。上游时间只认 upstream_commit_at,没有就不显示。

3 · 商店 changelog(商店自己的活人感)

「公告&复盘」拆出社区后的新家(ADR 0017),build in public 的载体
形态/changelog 静态页:按周一条,人写摘要(本周做了什么、为什么)+ 自动统计行(本周新收录 N 条、新包 X——由 build-index meta 派生)。署名 + 日期。
数据手写部分落 catalog/changelog.json(数组,append-only);自动行构建期算。不建 CMS、不做评论。
语气对用户说人话,不是 release note:「上新了 3 套视频制作的组合」而非「feat: packs+3」。内部词汇红线同样适用。
导航页脚入口即可,不占 nav 主位(nav 维持四项;若社区入口按 ADR 0017 摘除,changelog 可暂顶其位,密度达标后归还)。

4 · 排序、验收与明确不做

做的顺序

① 包手记(纯内容,当天可上)→ ② changelog 页(轻,顺手立 build in public 节奏)→ ③ 作者行(含 ingest 小增项 upstream_commit_at,随下次采集起攒)。

验收

  • 8/8 包页有署名手记,措辞过零内部词汇自查
  • /changelog 首条发布(含自动统计行)
  • 详情页作者行上线;无 upstream_commit_at 的条目整段隐藏、无占位

明确不做(P0 边界)

  • LLM 代写手记/周报后直接上架——机器装人红线;草稿可以,定稿必须人签
  • 评论、账号、回执——那是 M1(ADR 0017 §排期)
  • /community 聚合页、作者头像、产物画廊——密度/版式/IP 各有门槛,后置
