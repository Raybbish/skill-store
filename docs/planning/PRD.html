一句话

为所有兼容 Agent Skills 标准的 AI agent 建一个以安全透明、可复现评测、效果可见为核心的 skill 商店:发现已是红海,我们卖的是信任。

1概述与背景

Agent Skills(SKILL.md)自 2025 年 10 月由 Anthropic 发布、2026 年初开放为独立标准后,已被约 40 个产品兼容(Claude Code、Codex、Cursor、Copilot、Gemini CLI 等)。生态供给在 20 天内增长 18.5 倍,skills.sh 半年索引约 67 万个 skill。但供给爆发的另一面是:47,150 个公开 skill 平均质量分仅 6.2/12,36.8% 至少含一个安全缺陷,13.4% 含严重问题,已确认 76 个恶意 skill。现有 8+ 家市场全部聚集在「目录/发现」层,没有一家把质量与安全做成可比较、可验证的货架信号。

67 万skills.sh 索引量
6.2/12公开 skill 平均质量
36.8%含安全缺陷比例
0 家做可复现评测的商店

2问题定义与机会

用户侧痛点

① 不敢装:SKILL.md 里三行 markdown 即可外传 SSH 密钥,用户无从判断;② 不会选:同类 skill 十几个,没有可比较的质量信号,只能看安装量(马太效应+可刷);③ 不知道有什么用:纯文字描述无法传达「装了之后输出会变成什么样」;④ 成本不透明:skill 增加每次调用的 token 消耗,无任何平台披露。

市场空白

竞品全景(详见附录调研报告):skills.sh/SkillsMP 是无审核目录;ClawHub 审计属事后补救且多次失守;Agensi 有安全检查但无质量评测;SkillHub(中文市场)只有粗粒度 S/A/B/C 评级。「可复现评测协议 + 结构化安全披露 + 效果对比」三件套在全市场为空白,且均已被学术界(SkillsBench)和安全界(Snyk)验证为真实需求。

3目标用户

角色典型场景核心诉求阶段
Agent 重度开发者用 Claude Code/Cursor 日常开发,想扩展 agent 能力快速找到「真的有用且不会偷数据」的 skill首发
非技术办公用户用 Cowork/Copilot 做文档、表格、汇报看得懂的效果对比与一键安装,不想读代码首发
Skill 开发者(供给端)写了 skill 想获得分发和回报公平的曝光机制(靠质量而非刷量)、认证背书M1
企业买家为团队统一采购/管控 skill安全合规审计、私有货架、权限管控M2+

4定位与差异化

定位:多 agent 中立的「认证商店」,与纯目录的关系类似 App Store 与「网上随便下软件」的关系。五个差异化点全部零竞品覆盖:

#差异化说明验证依据
1可复现评测协议(赛道非裁判)任务集 + 确定性校验器 + runner 开放成可复现协议(npm run eval 谁都能跑);货架分数带 runner/模型元数据、可复现可挑战,平台不做单方裁判SkillsBench 证明质量差异真实(+16.6pp);公信力锚在可复现性而非背书
2权限营养标签结构化披露五风险因子:scripts / network / filesystem / env / commands,附文件级证据Snyk 证明单一「通过/不通过」不可信;aiskillstore 已有同款数据模型可继承
3效果对比替代截图同一 prompt 装/不装的输出对比,评测管线自动产出原型已验证展示形态
4Token 成本标注标注每次调用的上下文加载量(如 ~3K token/次)GPT Store 教训:token 成本吃掉收益是头号坑
5跨平台热度聚合同一 skill 在 skills.sh / ClawHub 等各平台的安装量合并视图各 hub 数据孤岛,无人做合并
平台做「赛道」不做「裁判」是核心产品表达:评测协议开放、分数带元数据可复现可挑战,公信力锚在可复现性而非官方背书,与「已扫描≠保证安全」同构。评测榜在协议成熟前以「可复现评测·开发中」路线图态呈现,流行度(安装量/stars)榜先行。

6供给管线

详见架构图(供给聚合架构图.html)。要点:

供给源与优先级(2026-07-03 校正):① 官方精选仓(anthropics/skills、vercel-labs、合作伙伴仓,licence 清晰,第一批搬)→ ② awesome 精选仓(hub-signals:取「被收录+归类」信号,内容回上游)→ ③ GitHub 全域(topic:claude-skills 搜索,公开稳定 API,已作为可靠主采集通道)→ ④ skills.sh(私有 /api/v1 实测 401 不可用,当前仅解析首页 SSR 榜单取热度信号)。第三方 Hub / 榜单只取热度/精选信号、不搬内容,一律回上游仓库采集;高危来源全量过审,无免检通道。

采集管线(定时 GitHub Action):git clone --depth 1 + 文件树(ls-tree,无 REST 限流)→ frontmatter 校验 → 元数据提取(licence/scripts)→ 采集期归类(打 category/tags)→ 规范 ID(owner/repo/name 三段式)→ 内容哈希去重(fork/复制合并溯源)→ 记录上游 commit SHA;每日 diff 上游,变更即重审。

许可证分流(数据模型第一天就要区分):托管型 MIT/Apache 等宽松 licence → 镜像副本、可打包分发;索引型 无 licence/专有 → 只存元数据 + 跳转上游,配 DMCA 下架流程。

质量漏斗:全量索引(~100 万,只存元数据,近零成本)→ 头部候选(~5 千,按安装量/星标/活跃度)→ 审计+评测 → 认证货架(~2 千)。「已索引 100 万 / 已认证 2 千」的稀缺性本身即品牌叙事。

7评测与安全系统(核心资产)

7.1 质量评测

方法对齐 SkillsBench:按品类构建标准任务集(prompt + 预置输入 + 确定性校验器,不用 LLM 主观打分);隔离沙箱执行,装/不装双跑。平台做「赛道」不做「裁判」:任务集 + 校验器 + runner 开放成可复现评测协议(npm run eval 谁都能跑),货架分数标注 runner 与模型、带元数据可复现可挑战——公信力锚在可复现性,而非平台单方背书。诚实性红线:产物缺失 / 环境不匹配记 N/A(不计 0 分)并排除出统计;只有带模型元数据、且无 N/A 任务的真实结果才回写货架(写入闸);平台只对少数精选条目跑分兜底。评测协议与历史数据本身沉淀为核心资产。

7.2 安全审计(四层 + 人工分级)

层手段作用
L1 静态签名YARA 规则 + 正则(密钥、危险命令)拦已知恶意模式,近零成本
L2 脚本分析附带 Python/Node 脚本的数据流追踪抓「读凭证→外传」路径
L3 LLM-as-judge模型审查 SKILL.md 指令意图唯一能抓新型提示注入的一层(实测 19/19),最贵但不可省
L4 动态沙箱实际执行,校验「文档声称 vs 代码实际」一致性对付「说明人畜无害、脚本藏后门」

产出风险五因子标签(scripts / network / filesystem / env_access / external_commands)+ 文件级证据,继承 aiskillstore 的 skill-report.json 数据模型;审计报告随 Git 仓库公开、PR 留痕。含外联或扫描存疑的 skill 进入人工复核队列,货架显示「待复核」而非绿勾。开源扫描器(Cisco skill-scanner、SkillScan)可作为 L1-L3 的起点。

措辞红线:四层叠加仍拦不住全部 LLM 生成的隐蔽攻击(ClawHub 漏网为证)。全站永远用「已扫描/已评测」,禁用「保证安全」;权限标签的定位是结构化披露、辅助用户自行判断,不是安全背书。

8非功能需求

架构:继承 aiskillstore 验证过的三条——Git 仓库为唯一事实源(变更走 PR)、每条 DB 记录带 commit 溯源、关键/非关键路径分层(同步硬失败重试,算分容忍部分失败,缓存失效仅告警,翻译异步 fire-and-forget)。所有批处理做单项隔离 + 指数退避,部分成功永远好过整体失败。成本:LLM 审计与评测是主要边际成本,做批量/分片调度与新鲜度截止线(过期才重审),按「头部候选」规模而非全量做预算。合规:DMCA 响应流程、审计证据不含用户数据、只镜像宽松 licence 内容。性能:目录页静态化 + CDN,详情页数据缓存 24h 自然过期。

9商业模式

核心教训(GPT Store):变现必须跟着高质量供给走,不能反过来。分三阶段:

阶段模式说明
M0-M1 免费不收费,攒信任与数据评测数据与安全报告积累是唯一目标;LLM 审计有边际成本,天然构成后续付费的价值基础
M1-M2 认证服务开发者付费加急审计/认证徽章;买断制付费 skill(创作者 70% 分成,对标 Agensi)认证含金量取决于评测公信力,先有公信力再收费
M2+ 企业订阅私有货架 + 合规审计报告 + 团队管控企业是安全审计付费意愿最强的客群

10冷启动策略

供给侧:按第 6 节顺序,首周用官方精选仓保证货架不空,第二批接 skills.sh 头部(自带安装量数据可展示)。信任侧:冷启动期评论区由「平台审计摘要」占位(原型已含此设计),解决无评价的鸡生蛋问题;审计报告全部公开在 GitHub 仓库,可被第三方验证。需求侧:以「可复现评测报告」做增长——每周发布一个品类的评测(如「6 个 PPT skill 实测,附可复现跑法与元数据」),评测数据即内容营销素材,天然可被搜索引擎与社区引用。

12成功指标

北极星:经由本站安装且 30 天后仍在使用的 skill 数(信任的最终度量)。过程指标:认证 skill 数与覆盖品类、评测报告被外部引用次数、安装→评论转化率、开发者主动提交数。反指标(需守住):认证 skill 被确认恶意的数量(目标恒为 0,出现即触发公开复盘)、评测分与真实好评率的背离度(防评测集被针对性过拟合)。

13风险与对策

风险可能性/影响对策
平台截流:Anthropic/Vercel 把评测+安全做进官方渠道中 / 致命多 agent 中立聚合(官方各管自家);评测任务集与历史数据沉淀为独占资产;跨平台热度聚合官方做不了
认证 skill 漏网恶意,信任崩塌中 / 致命四层审计+人工分级;措辞留余地;出现即 24h 内下架+公开复盘;高危来源(ClawHub)无免检
评测被刷:开发者针对开放任务集过拟合高 / 中可复现协议下靠定期轮换任务 + 多 runner/模型交叉 + 评测分与用户评价背离监控(而非靠保密);社区可复跑挑战存疑分
审计/评测成本失控中 / 高漏斗控制受审规模;新鲜度截止线避免重复审计;批量调度用低价模型跑 L1-L2 预筛
许可证纠纷低 / 中托管/索引双轨制;DMCA 流程;只镜像宽松 licence
