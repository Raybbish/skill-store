# 供给与采集设计(架构图 ①② 层实现文档)

> 对应供给聚合架构图的「① 供给源」与「② 采集」两层。描述以代码实际行为为准。
> 更新:2026-07-02 · 代码位置:`packages/pipeline/src/`

## 总览

一句话数据流:**五个供给源发现 skill → 统一回上游 GitHub shallow clone 采集 → 校验/提取/去重 → 写入 `catalog/`,每日 GitHub Action 自动跑,产出走 PR 人工抽查。**

核心设计原则:

1. **情报不当货**。skills.sh、awesome-list 等第三方站只提供"哪里有 skill、谁被精选、装了多少次"的**发现与信号**,内容一律回上游 GitHub 仓库采集,不搬运、不镜像任何第三方数据库。
2. **收录有门槛,拒绝全量灌注**。GitHub 上存在批量生成型仓库(实测单仓最多 26,134 个 SKILL.md)与聚合搬运型仓库。管线通过"每仓折叠采样 + 合集条目"控制供给质量,这是与 SkillsMP(180 万条全收、噪音极大)的根本差异。
3. **采集只写元数据,不冲掉下游成果**。安全审计、评测、人工复核的结果在同 id 更新时全部保留;内容未变化时连文件都不重写(幂等,git diff 无噪音)。
4. **归属还原**。同内容多处出现时,canonical 归属按"已有条目 > 官方源 > stars 最高"裁决,搬运仓标记 `duplicate_of` 指回原作者。已调研的竞品(skills.sh / buildwithclaude / SkillsMP)均为先到先得或不去重,此为差异点。

## ① 供给源

五个源按信噪比排序接入,全部汇入同一条采集管线。架构图中「awesome 精选仓」与「第三方 Hub 情报」在实现里合并为 hub-signals 一条线(精选清单既是内容线索也是信号)。

### 1. 官方精选仓(默认必跑)

- **入口**:`npm run ingest`(无需 flag);`--source <repo>` 可只跑单仓
- **来源**:`sources.yaml` 中 `type: github-repo` 的仓库,当前为 `anthropics/skills`、`vercel-labs/agent-skills`
- **特点**:量小质高、licence 清晰,是 catalog 的信任底座。owner 进入"官方源"名单,在去重裁决中优先级最高
- **扩源方式**:向 `sources.yaml` 加条目即可,无需改代码

### 2. GitHub 全域(`--github-search [N]`,默认 100)

- **实现**:`github-search.ts`。GitHub Search API 按 `topic:claude-skills` 搜仓库(`GH_SEARCH_QUERY` 可覆盖),stars 降序取头部 N 个,跳过 fork 与 archived,逐仓 clone 采集
- **信号**:每条注入 `signals.stars_github`(仓库级 stars)
- **防灌注(每仓折叠采样)**:单仓 SKILL.md 数超过 `MAX_PER_REPO`(默认 50)判定为批量源,只采样收录 N 条。采样优先级:frontmatter 合规 > 有 description > 原目录顺序(稳定排序,重跑结果一致)。被采样条目标 `signals.bulk_source: true`;所有条目记录 `signals.repo_skill_count`(仓内总数,供排序降权——2.6 万个 skill 分摊同一份 stars,单条含金量远低于单 skill 仓)
- **合集条目**:被折叠的仓库额外产出一条 `CollectionReport` 写入 `catalog/collections/<owner>/<repo>.json`(总数/采样数/stars/上游 URL),前端可渲染为"该仓含 N 个 skill → 去上游"的合集卡片。此机制参考 buildwithclaude 的 `isMarketplace()` 折叠,但保留了 skill 粒度采样
- **限制**:GitHub search 上限 1000 条;需 `api.github.com` 可达 + `GITHUB_TOKEN` 提升限流。topic 搜索召回有限,后续可加 Code Search(`filename:SKILL.md`)扩召回

### 3. awesome 精选信号(`--hub-signals [N]`,默认 300)

- **实现**:`hub-signals.ts`。拉取社区精选清单 README(默认 `VoltAgent/awesome-agent-skills`,`HUB_LISTS` 逗号分隔可扩),解析 `- [name](github-url)` 条目与所属分类标题,按上游仓分组回 GitHub 采集
- **信号**:注入 `signals.curated_by`(被哪些清单收录 + 分类)与 `meta.category`(补上采集拿不到的分类字段)
- **防灌注**:每仓上限 `MAX_PER_REPO`(默认 50);清单里带 subpath 的条目只收对应目录的 skill
- **合规性**:awesome-list 是 MIT 公开 markdown,本就以被引用为目的;"被精选"比纯流行度更契合本店质量定位

### 4. skills.sh 安装量榜(`--skills-sh [N]`,默认 200)

- **实现**:`skills-sh.ts`,解析首页服务端渲染的榜单(robots.txt 明确 `Allow: /`,`/api/` 才禁抓),从链接 `/<owner>/<repo>/<slug>` 与锚文本尾部安装量(`2.3M`/`613.6K`)还原条目,~280 条足够 top-200 信号。官方 `/api/v1` 文档声称免鉴权、实测 401 需申请 key,故不对接
- **匹配**:榜单条目按 slug 对上仓库内 skill 的目录名或规范化 name,匹配不上的静默跳过(该仓其他 skill 由 GitHub 全域源覆盖);`sourceType: well-known`(非 GitHub 源,如 open.feishu.cn)暂不支持
- **信号**:注入 `signals.installs_skills_sh`(去重后安装量)——"安装量 = 免费预筛"
- **验证记录**(2026-07-02):top 50 → 16 仓 → 58 skill,46 新增,重复 0
- **后续**:skills.sh 的 `/api/v1/skills/audit/{id}` 返回 Snyk/Socket/Gen Trust Hub 等伙伴审计结果(status/riskLevel),W2 安全扫描可作免费外部对照信号

### 5. 供给源对照表

| 源 | flag | 发现方式 | 注入信号 | 防灌注 |
|---|---|---|---|---|
| 官方精选仓 | (默认) | sources.yaml 白名单 | — | 白名单本身 |
| GitHub 全域 | `--github-search` | topic 搜索,stars 头部 | stars_github, repo_skill_count, bulk_source | 每仓折叠采样 + 合集条目 |
| awesome 精选 | `--hub-signals` | 清单解析回上游 | curated_by, category | MAX_PER_REPO + subpath 过滤 |
| skills.sh | `--skills-sh` | 安装量榜(API/SSR) | installs_skills_sh | 榜单本身即预筛;isDuplicate 跳过 |

## ② 采集管线

所有源殊途同归:拿到 `owner/repo` 后进入 `discoverFromRepo()`,再由 `ingest.ts` 统一去重写入。逐环节:

### 1. shallow clone(`git.ts`)

`git clone --depth 1` 到临时目录(相比 REST API 无速率限制、一次拿全仓),`git ls-tree -r HEAD` 取全量 blob 清单(path + git blob sha),记录 HEAD commit 与分支名。采集结束 cleanup 删除临时目录。

### 2. SKILL.md 发现

对文件树按正则 `(^|\/)SKILL\.md$` 匹配,每个命中目录即一个候选 skill(根目录 SKILL.md 也支持)。

### 3. frontmatter 校验(`frontmatter.ts`)

按 agentskills.io 最小规范:YAML frontmatter 存在、`name` 非空且 ≤64 字符、`description` 非空且 ≤1024 字符。结果写入 `frontmatter_valid` / `frontmatter_issues`,**不合规不拒收**(货架标记,由下游处置),但在折叠采样时排序靠后。

### 4. 元数据提取

- **licence 双轨分流**(`license.ts`,设计文档 §4):skill 目录内有自己的 LICENSE 以目录级为准,否则回落仓库根 LICENSE。文本朴素识别(MIT/Apache-2.0/BSD/ISC/Unlicense/CC0);识别为宽松集合 → `hosting: mirrored`(可镜像托管),识别不出 → `local-file(needs-review)` / `none(all-rights-reserved)` → `hosting: indexed`(仅索引跳转上游)
- **脚本静态清点**(`hash.ts`):按扩展名(py/sh/js/ts/rb/ps1/exe 等)清点目录内可执行文件,写入 `security_audit.risk_factors.scripts` 与 evidence(前 20 个)。这是 pre-audit 提示,非审计结论;其余四个风险因子(network/filesystem/env_access/external_commands)置 null 待 W2 审计填充
- **上下文体积**(ADR 0015):写入 `context_size`,只表达静态装载边界,不承诺真实每次调用消耗。三类 scope:最小装载(`SKILL.md`)、含声明引用(`SKILL.md` + 明确相对路径文本资源)、文本包总量(skill 目录内可读文本)。旧 `token_cost.body_tokens` / chars/4 链路已下线。

### 5. 规范 ID 与 content_hash

- **ID(三段式 v2)**:`小写owner/小写repo/normalizeName(frontmatter.name || 目录名)`,与架构图 `owner/repo/path` 及 skills.sh 的 `{source}/{slug}` 对齐,消除同 owner 跨仓同名撞 id。目录遍历统一走 `catalog.ts` 的 `loadCatalogEntries()`;存量迁移脚本 `jobs/migrate-id-v2.ts`(已执行,73 条,审计/复核结果无损)
- **content_hash**(`hash.ts`):对目录内全部 (相对路径, git blob sha) 排序集合取 sha256。git blob sha 本身内容寻址,**无需读文件内容即得稳定指纹**;CLI 安装时可用同算法本地校验
- **溯源锚点**:`upstream`(仓库内路径 URL)+ `upstream_commit`(采集时 HEAD),支撑每日 diff 与哈希漂移检测

### 6. 去重与归属还原(`ingest.ts`)

跨运行 + 跨源,以 content_hash 为键:

1. 用已有 catalog 预填哈希表,**已有条目优先当 canonical**(稳定,不因重跑漂移;优先取本身非 duplicate 的条目,避免链式指向)
2. 本次新出现的哈希,同哈希组内裁决:**sources.yaml 官方源 owner > stars 最高者**(官方源不注入 stars,必须显式优先,否则会输给搬运它的高星聚合仓)
3. 组内其余条目标 `meta.duplicate_of: <canonical id>`;同 id 覆盖更新不算重复
4. 另有同 id 去重:一次运行内同 id 只保留第一条(源顺序:官方 → hub → github-search → skills.sh)

### 7. 写入 catalog(幂等)

- 路径:`catalog/skills/<owner>/<repo>/<name>/skill-report.json`(符合 `skill-report.schema.json`)
- **未变跳过**:content_hash 与 upstream_commit 都没变 → 不重写文件,无噪音 diff
- **下游成果保留**:同 id 更新时,若已有审计结果(status ≠ pending 或有人工 review)则原样保留(上游内容变化由 audit 的哈希漂移检测触发重审),eval 结果同理
- **两段式镜像**:默认索引层只写元数据;`--mirror`(`INGEST_MIRROR=1`)且 licence 为 mirrored 时才拷贝完整副本到 `mirror/`(symlink 解引用落地为真实文件)
- **合集条目**:`catalog/collections/<owner>/<repo>.json`,字段(skill_count/sampled_count/stars)没变不重写
- 汇总统计:新增 / 更新 / 未变跳过 / 重复 / 保留审计 / frontmatter 不合规 / 批量源合集

## 调度与运行

### 本机

```bash
export GITHUB_TOKEN=$(gh auth token)
npm run ingest                                        # 仅官方仓
npm run ingest -- --github-search 100                 # + GitHub 全域
npm run ingest -- --hub-signals 300                   # + awesome 精选
npm run ingest -- --skills-sh 200                     # + skills.sh 榜单
npm run ingest -- --source anthropics/skills          # 只跑单仓
npm run ingest -- --mirror ...                        # 托管层:下载镜像副本
```

### GitHub Action(`.github/workflows/ingest.yml`)

- 每日 03:00 UTC cron,全源:`--github-search 100 --hub-signals 300 --skills-sh 200`,timeout 120 分钟
- `workflow_dispatch` 手动触发可指定单仓 source
- 产出不直接进主干:`peter-evans/create-pull-request` 开 PR(分支 `ingest/<run_id>`),人工抽查 licence 分流、frontmatter 不合规、duplicate_of、合集条目后合并
- Secrets:`GITHUB_TOKEN`(自带)

### 环境变量总表

| 变量 | 默认 | 作用 |
|---|---|---|
| `GITHUB_TOKEN` | — | GitHub Search API 限流提升 |
| `GH_SEARCH_QUERY` | `topic:claude-skills` | 全域搜索 query |
| `MAX_PER_REPO` | 50 | 每仓折叠采样上限(github-search 与 hub-signals 共用) |
| `HUB_LISTS` | `VoltAgent/awesome-agent-skills` | 精选清单,逗号分隔 |
| `INGEST_MIRROR` | — | `1` = 托管层,下载镜像副本 |
